# C语言代码注释约束规则 (C Coding Comment Constraints)

## 0. 使用前强制确认 (Pre-use Confirmation)
- **强制询问**：在应用本规范为任何项目编写或生成注释之前，**必须**先向项目负责人（或用户）明确确认以下三项配置，并依据确认结果调整后续注释中的风格、编码和特殊注意事项：
  1. **编码格式**：源文件统一使用的字符编码（如 `UTF-8 without BOM`、`GB2312/GBK` 等）。
  2. **注释风格**：选择 `/* */` (C89) 或 `//` (C99) 作为项目统一的注释风格。
  3. **开发环境**：使用的集成开发环境（IDE）及版本（如 Keil µVision、VS Code、CLion 等），并关注其对中文和编码的支持情况。
- **记录与遵循**：确认结果须明确记录，并作为后续所有注释生成的唯一依据。未经确认，**不得**盲目套用本规范中的默认设置。

---

## 1. 通用风格
- **统一性**：整个项目必须统一使用 `/* */` (C89) 或 `//` (C99) 风格，严禁混用。
- **禁止嵌套**：严禁使用 `/*` 嵌套 `/*`，这会导致编译错误。
- **逻辑优先**：注释必须解释“**为什么 (Why)**”和“**是什么 (What)**”，严禁复述代码本身的“怎么做 (How)”（如 `i++;//i加1` 视为无效注释）。

## 2. 文件头约束 (File Header)
每个 `.c` 和 `.h` 文件顶部**必须**包含以下元数据块：
- 文件名 (`@file`)
- 简要功能描述 (`@brief`)
- 作者 (`@author`)
- 日期 (`@date`)
- 版本记录 (`@version`) 及修改日志 (`@remarks` 或修改记录表格)。

## 3. 函数注释约束 (Function Documentation)
所有对外公开（声明在 `.h` 中）的函数，**必须**使用结构化标签：
- 使用 `@brief` 描述功能。
- 使用 `@param[in/out]` 描述参数含义及方向。
- 使用 `@return` 描述返回值含义。
*(注：私有静态函数建议保持同等标准)*。

## 4. 变量与宏约束 (Variable & Macro)
- **宏定义**：必须在定义行末尾或紧邻上方，注释其物理含义、取值范围及单位（如时间单位、精度）。
- **全局变量**：必须在声明处注释其用途、取值范围及所属模块。
- **结构体/枚举**：必须注释结构体整体功能，且**每个成员变量**必须使用行尾注释说明。

## 5. 预处理器约束 (Preprocessor)
- 复杂的条件编译块（`#ifdef` / `#ifndef`），在对应的 `#else` 和 `#endif` 末尾**必须**添加条件表达式标签，明确归属。例如：`#endif /* USE_FEATURE_X */`。

## 6. 废弃代码处理 (Deprecated / Dead Code)
- **严禁**使用 `/* ... */` 注释掉大段代码（易导致嵌套灾难）。
- 临时屏蔽代码**必须**使用 `#if 0 ... #endif` 结构，并附加说明屏蔽原因。

## 7. 特殊标记约束 (Todos & Warnings)
- 待办事项**必须**使用 `TODO(责任人): 描述` 格式。
- 已废弃接口**必须**使用 `@deprecated` 标签，并指明替代方案。

## 8. 量化指标
- 有效注释量（不含纯重复性符号）应占源文件总行数的 **20% 以上**（参考行业规范）。

## 9. 编码规范约束 (Encoding Constraint)
- **文件编码统一**：所有源代码文件（`.c`、`.h`）**必须**统一使用 **UTF-8 without BOM** 或 **GB2312/GBK** 编码，并在团队内保持一致。
- **禁止中文乱码**：注释中的中文字符**必须**确保在目标开发环境（如 Keil、VS Code、CLion）中正确显示。
- **Keil 特别提醒**：若使用 Keil，建议将 Editor 编码设置为 **"Chinese GB2312(Simplified)"** 或 **"Encode in UTF-8 without signature"**，并避免在注释中使用生僻字或特殊符号。
- **跨平台项目**：若项目在 Windows/Linux 间协作，**强制要求**使用 **UTF-8 without BOM**，并在文件头或项目 README 中明确标注。
- **禁止使用全角字符**：除中文注释正文外，代码中的英文标点、括号、运算符**严禁**使用全角形式（如“，”“（”“）”等）。
- **提交前检查**：每次提交代码前**必须**检查新增注释是否存在乱码，确保所有 IDE 显示正常。
